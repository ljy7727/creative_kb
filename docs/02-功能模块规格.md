# 创作知识库 · 功能模块规格

> 每个模块给出：功能点、交互、AI 流水线（提示词契约）、验收标准。实现时以此为唯一依据，UI 细节可在 Material 3 规范内自由发挥。

## 模块A：Agent 中枢（core/llm + core/tasks + 设置页）

### A1 LlmClient 接口
```dart
abstract class LlmClient {
  /// SSE 流式对话。onDelta 逐段回调；返回值含 usage（各厂商在最后一个 chunk 的 usage 字段，缺失时按字符数/4 估算并标记 estimated=true）
  Future<ChatResult> chat({
    required ProviderConfig provider,
    required String model,
    required List<ChatMessage> messages,
    double? temperature, double? topP, int? maxTokens, Map<String,dynamic>? extra,
    void Function(String delta)? onDelta,
  });
  Future<List<ModelInfo>> listModels(ProviderConfig provider);   // GET {baseUrl}/models
  Future<List<List<double>>> embed({required String model, required List<String> texts});
  Stream<...> 如需流式 UI 再暴露 chatStream；无网络/401/429/5xx 抛类型化异常
}
```
OpenAI 兼容实现基于 dio：`POST {baseUrl}/chat/completions`，`stream:true` 手写 SSE 解析（按 `\n\n` 分帧、取 `data:` 行、忽略 `[DONE]`）。

### A2 厂商预设
内置 4 预设（DeepSeek/通义千问/豆包/智谱，baseUrl 见 01 文档）+ 自定义（任意 baseUrl）。设置页「添加厂商」：选预设或自定义 → 填 API Key（写入 secure storage，数据库只存 keyRef）→ 「拉取模型」按钮调 listModels 入库。

### A3 模型标签（启发式）
`modelId` 匹配：`reasoner|r1|thinking|o1|o3` → reasoning；`embed` → embedding；厂商文档上下文 ≥64k（内置一张常见模型上下文表）→ +long_context；默认 general。UI 显示标签 chips，点击可改（改后 isActive 保持、tags 覆盖）。标注文案注明「自动识别，可手动修正」。每个用途的下拉框默认推荐：结构化入库/深度任务→reasoning 优先；日常优化→general；向量化设置→仅 embedding。

### A4 思考强度预设（intensity_presets，builtin 4 条 seed）
| code | 名称 | 参数 |
|---|---|---|
| fast | 极速 | temperature 0.3, maxTokens 2048 |
| standard | 标准 | temperature 0.7, maxTokens 4096 |
| deep | 深度 | temperature 0.5, maxTokens 8192, extra: {请求分步思考, 厂商自适应推理参数}（DeepSeek 换用 reasoner 模型时由推荐逻辑处理） |
| custom | 自定义 | 用户可编辑 temperature/topP/maxTokens |
所有 AI 发起处均有强度选择器（默认 standard，设置页可改全局默认）。

### A5 任务队列与记账
- TaskRunner：`PendingQueue` 内存队列 + task_queue 表持久化；并发 1；启动时把遗留 running 重置为 pending
- 每个任务：状态机 pending→running→success/failed/cancelled；网络类异常与 JSON 校验失败自动重试 ≤2（指数退避 2s/8s）；超时 120s
- 记账：成功/失败都写 usage_log；估算费用查内置价格表（常量表：模型名前缀→每百万 token 输入/输出单价，覆盖 deepseek-chat/reasoner、qwen-plus/max/turbo、doubao-pro/lite、glm-4 系列、embedding 系列；查不到记 null）
- 额度防护：单次任务 maxTokens 不超过「单次上限」设置；发起新任务前查当日累计，超过「日上限」直接 blocked 并弹提示
- 用量看板（features/usage）：今日/累计 token、按模块饼图、按模型柱状图、最近 50 条明细表、费用列（无价则 "—"）

### A6 GitHub 更新检查
`update_checker.dart`：`GET https://api.github.com/repos/{owner}/{repo}/releases/latest`（设置页配置 owner/repo，默认占位 `ljy7727/creative_kb`；404 视为未发布，静默）。semver 比较当前 `pubspec version` 与 tag；有新版 → 对话框展示 Release Notes（markdown 渲染）+ 按钮「前往下载」：桌面 `url_launcher` 打开 Release 页；Android 直接打开 `.apk` 资产链接。设置页「检查更新」手动触发 + 「启动时自动检查」开关（默认开）。

## 模块B：灵感碎片（features/fragments）

### B1 录入页（模块首页顶部常驻）
- 多行输入框（Enter 换行，Ctrl+Enter 提交）+ 「AI 优化后保存」复选框 + 强度选择器 + 标签快速输入
- 勾选 AI：保存 rawText(status=raw) → 入队 FragmentOptimizeTask → 完成后 status=optimized 并展示
- 未勾选：直接存 raw，status=raw

### B2 FragmentOptimizeTask 提示词契约
系统提示词（要点，实现时写成完整中文 prompt）：「你是创作灵感整理助手。将口语化/混乱的输入整理为标准灵感条目，只输出 JSON：`{"items":[{"title":str,"content":str(整理后的完整表述,Markdown),"tags":[str],"context":str(可选,补充背景)}]}`。要求：纠错润色；剥离语气词保留核心创意；一条输入含多个独立灵感时拆成多条 items；标签形如 `#主题-子类`；不得编造原输入没有的事实性信息，不确定的保留原表述并加 "(存疑)"。」
- 输出经 structured_output 校验 → 多条则插入多行 fragments（source='ai'，aiMeta 记录模型/强度/token）
- 列表页：标签筛选 chips、FTS 关键词搜索（复用 kb_fts 之外的 fragments 简易 LIKE 即可，量小）、按时间倒序
- 详情页：原始/AI 双版本切换对比（左右或上下两个卡片）、「转为提示词草稿」（跳模块C生成页并预填）、「转为资料条目」（跳模块D入库向导并预填）、「重新优化」（换强度重跑）

### B3 验收
- 示例（方案原文的唐朝笏板口语输入）→ 产出结构化条目 + 3 个左右标签；含两个主题时正确拆分
- 无 Key 时：可手动录入/编辑/删除，AI 复选框 disabled 并带引导

## 模块C：提示词库（features/prompts）

- 类型三种：novel（小说写作）/ image（AI 绘画）/ agent（Agent 指令），每类内置一个骨架模板常量（角色设定/任务目标/约束/输出格式 四段式；image 类为：主体/风格/构图/画质词 四段式）
- 「从碎片生成」：选碎片（可多选）→ 选类型与强度 → 生成 3 个风格版本（一次任务输出 JSON `{"versions":[{"style":"精简"|"详细"|"创意","body":str}]}`）→ 三卡对比选择保存
- 「定向优化」：选提示词 → 方向（精简压缩/扩写丰富/适配特定模型/风格转换）→ 新版本入 prompt_versions，currentVersionId 前移，详情页可看历史并一键回滚
- 「变量提取」：分析 body 输出 `{"variables":[{"name":str,"desc":str}]}`，正文同步标注 `{{变量名}}`；详情页变量面板可复制填充后的最终文本（弹窗填值→替换→复制）
- 分类管理：自定义分类字符串 + 类型筛选；FTS 搜索

## 模块D：创作资料库（features/kb）——核心模块

### D1 Schema 注册表
应用数据目录 `schemas/*.json`，首启 seed 4 套（通用=方案原文的基础 Schema；历史官职：朝代/品级/职权/上下级；仙侠宝物：品级/材质/功效/炼制方式/稀有度；宗门势力：层级/驻地/传承功法/核心人物/敌对势力）。每套：`{id, name, matchKeywords[], fields[{key,label,type(enum/text/markdown/number),required}], baseSchema沿用通用字段}`。设置页可查看/编辑/新增（编辑即改 JSON 文件，热加载）。

### D2 入库向导（五步，单页向导流）
1. **输入**：大文本框粘贴 或 file_picker 选 1 个 txt/md 文件读入；（预填模式：从碎片跳入时已有初始文本）
2. **AI 清洗+分类**：KbIngestTask 输出 JSON：`{"cleaned":str(去广告冗余后的正文),"proposedCategory":str(路径,"未分类"兜底),"proposedSchemaId":str,"entries":[{"entryName":str,...通用字段+扩展字段}]}`（长文多主题时输出多个 entries；系统提示词附完整分类树现状 + Schema 注册表摘要）
3. **校验映射**：逐 entry 按 Schema 校验；分类路径自动创建 kb_categories；用户可改分类/字段
4. **预览确认**：条目卡片列表（Markdown 渲染），支持编辑；「极速入库模式」开关（设置页，默认关；开则跳过本步直接入库）
5. **入库**：写 kb_entries；`related` 数组与库内 entryName 精确匹配建立 kb_relations 双向行，未匹配的留空展示「待创建」；FTS 触发器同步；若配置了 embedding 模型 → 入队向量任务（失败不阻塞入库，UI 标「未向量化」）

### D3 关联建议（入库任务附加输出）
entries 内每条带 `relatedEntries:[entryName]`（AI 基于分类树与库内已有名称判断，提示词明确「只引用确定存在的名称」）。条目详情页展示双向关联列表，点击跳转。

### D4 检索页
- 单一搜索框：关键词（FTS5，name/summary/content 加权 name 3:summary 2:content 1）+ 语义（配置 embedding 时，查询文本向量化后余弦 topN）混合排序 `score = 0.6*fts归一 + 0.6*cos`，未配置则纯 FTS 并提示
- 左侧分类树（可折叠，含每类计数），右侧结果列表（标题/摘要/标签/可信度色点），点击进详情
- 详情页：Markdown 渲染、扩展字段表格、关联跳转、编辑（重新走校验）、删除（连带清理 relations/embeddings/FTS）

### D5 验收
- 方案原文「青云宗」示例段落 → 生成宗门势力条目，分类自动落到「仙侠设定/势力宗门」，扩展字段正确填充，正文为结构化 Markdown
- 检索「宗门 护山大阵」FTS 命中；配置 embedding 后语义查询「修仙门派的组织架构」也能召回该条目

## 模块E：设置（features/settings）与数据导出
分组页：厂商与 Key（A2/A3）、思考强度默认值、额度（单次/日上限）、Schema 注册表管理、更新（owner/repo、自动检查、立即检查）、数据（全量导出 zip=SQLite+schemas+Markdown 目录；导入=选择 zip 校验版本后整体替换，操作前自动再导出一份备份）。

## 附：全局验收清单
1. 首启无任何配置 → 五个页面可浏览，空态引导正确
2. 配置 DeepSeek Key（测试用假 Key 亦可验 UI 流程，接口 401 有明确错误提示）→ 拉模型列表成功展示与标签
3. 三大模块 AI 流水线在无 Key/超时/模型输出非法 JSON 三种情况下均有可理解的用户提示
4. 额度设为极小值 → 任务被 blocked 且用量页可见记录
