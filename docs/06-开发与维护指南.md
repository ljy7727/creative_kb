# 创作知识库 · 开发与维护指南（v0.7）

> 面向接手的开发者/Agent：读完本文即可了解项目结构、数据模型、约定、开发与发版流程。
> 设计背景见 `docs/00`–`docs/04`；本文描述的是**当前代码现状**（以本文为准）。

## 1. 项目概览

- 产品：本地优先的创作知识库（灵感碎片 / 提示词库 / 资料库 / 书籍 / 备忘录 / 密码本 / 用量 / 设置）。
- 形态：Flutter 单代码库，Windows 桌面 + Android；GitHub Releases 分发，应用内检查更新。
- 仓库：https://github.com/ljy7727/creative_kb （公开）
- 数据：全部本地 SQLite；AI 能力使用用户自配的厂商 API Key（多厂商 OpenAI 兼容协议）。

## 2. 技术栈

Flutter 3.47 / Dart 3.13 · Material 3 · flutter_riverpod · drift(SQLite + FTS5 trigram) · dio
· flutter_secure_storage · cryptography(AES-GCM) · flutter_markdown · file_picker · html
· open_filex(APK 安装) · archive(备份) · window_manager(Windows 窗口) · package_info_plus · intl

## 4. 数据模型（schemaVersion = 3）

| 表 | 关键字段 | 说明 |
|---|---|---|
| providers | name, baseUrl, keyRef, presetCode | Key 只存安全存储，keyRef 为引用名 |
| models | providerId, modelId, tags(JSON), isActive | 标签可手动改 |
| intensity_presets | code, params(JSON) | fast/standard/deep/custom |
| fragments | rawText, optimizedJson, title, tags, status | 原始/AI 双版本 |
| prompts / prompt_versions | type, body, variables, currentVersionId | 版本回滚 |
| kb_categories / kb_entries / kb_relations | path / entryName, summary, contentMd, extra(JSON), credibility | 条目与双向关联 |
| embeddings | entryId, model, vector(BLOB) | 语义检索（未配置则降级 FTS） |
| kb_fts | FTS5(trigram) | 由触发器与 kb_entries 同步 |
| usage_log | module, taskType, model, tokens, status | 记账与额度 |
| task_queue | module, taskType, payload, status | 队列审计 |
| app_settings | key, value | 单次/日额度、默认强度、更新仓库等 |
| memos | title, content, images(JSON 路径) | 图片在 `<appSupport>/creative_kb/memos/` |
| password_entries | name, fieldsEnc, noteEnc | 字段/备注 AES-GCM 密文 |
| books / book_chapters | title, author, kind(self/imported/builtin), sourceUrl, builtinKey / chapterIndex, content | 内置书用 builtinKey 去重 |

**迁移约定**：新增表时在 `database.dart` 注册表与 DAO，`schemaVersion` +1，并在 `onUpgrade`
中 `m.createTable(...)`（按 `from < N` 判断）。改 kb_entries 结构需重建 FTS（`rebuildFts`）。

## 5. 关键约定

1. **AI 调用链**：业务 → `KbAiGateway`/`StructuredOutput`/`LlmClient` → 厂商 HTTP；所有调用要
   记 `usage_log`（module/taskType），并在发起前检查日额度、以单次上限封顶 max_tokens。
2. **结构化输出**：模型只输出 JSON；解析失败把校验错误拼回消息重试 ≤2 次。
3. **安全**：API Key 只进 `flutter_secure_storage`；密码本字段 AES-GCM；URL 导入只允许
   http/https 且拒绝环回/私网/保留地址、限次重定向、限体积。
4. **状态管理**：每个 feature 一个 `providers/*.dart`；DAO 由 `appDatabaseProvider` 提供。
5. **UI 设计系统**：`lib/shared/theme.dart`（种子色 #0F766E；surface 色调分层、16 圆角卡片 +
   1px 描边、filled 输入框、8pt 间距）；新页面复用 `EmptyState`、Card、FilledButton.tonal 层级。
6. **内置书籍**：`assets/books/<dir>/book.json`，字段
   `{builtinKey,title,author,kind,sourceUrl,chapters:[{title,content}]}`；在
   `DefaultBookSeeder.assetPaths` 注册；废弃书把 builtinKey 放进 `obsoleteKeys` 自动清理。
   `kind=self` 可在应用内编辑，`builtin` 只读。

## 6. 开发流程

```bash
# 环境（Windows）：Flutter 在 C:/Users/Admin/flutter，需内联中国镜像变量
cd /d/AI/Project/creative_kb
export PUB_HOSTED_URL=https://pub.flutter-io.cn FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
C:/Users/Admin/flutter/bin/flutter pub get
C:/Users/Admin/flutter/bin/flutter analyze     # 必须 0 error
C:/Users/Admin/flutter/bin/flutter test        # 必须全绿
```

- 改表/DAO 后：`dart run build_runner build --delete-conflicting-outputs`。
- 新增页面：`features/<mod>/pages/` + providers；命名路由在 `core/router.dart` 与 `app.dart` 接线。
- 新增 AI 能力：优先复用 `StructuredOutput`/`LlmClient`；需要厂商专属接口（如 DeepSeek tools）
  放 `core/llm/`，业务层注入 provider 便于测试。
- 测试：与 lib 镜像；AI 用 fake 适配器/假网关，不访问网络；DB 用 `AppDatabase.inMemory()`。

## 7. 发版

1. 改 `pubspec.yaml` 的 `version`（如 0.7.0）。
2. `git commit` → `git push`（main）。
3. `git tag -a v0.7.0 -m "..." && git push origin v0.7.0`。
4. GitHub Actions：`ci.yml` 跑 analyze+test；`release.yml` 构建 Windows zip + Android APK 并发 Release。
5. 应用内「检查更新」按内置仓库 `ljy7727/creative_kb` 比对 semver。

## 8. 已知环境坑（Windows 开发机）

1. **项目路径必须 ASCII**：中文路径会让 Dart 分析服务器崩溃；`D:/AI/Project/知识库项目` 只是 junction。
2. **sqlite3 预编译 DLL**：`flutter test` 首次需从 GitHub Releases 下载；网络失败时用镜像下载
   `sqlite3.x64.windows.dll`（sha256 `2d389501...`）放入
   `.dart_tool/hooks_runner/shared/sqlite3/build/download-2d389501/sqlite3.dll`。
3. **Android release 需要 INTERNET 权限**：已显式写在 main AndroidManifest（缺失会导致所有网络失败）。
4. **Mimosa 安全钩子**：工作区内其它项目的高危 finding 会拦截 commit/push；poetry-kb 工作流会重置
   vendored 脚本，推送前如被拦按文档用 pathlib + `is_relative_to` 写法修复。
5. GitHub 直连不稳定：clone/下载失败时重试（IPv4/HTTP1.1），或走 API。
