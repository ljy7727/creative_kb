# 创作知识库 · 方案评估结论与设计决策

> 本文档是对原始需求方案的评估结果。所有开发任务以本文档的**决策**为准；与原始方案冲突之处，以本文档为准。

## 一、总体评估

原始方案完整度高：四层架构（界面 → 业务模块 → Agent 能力中枢 → 数据存储）划分合理，核心价值链「录入 → AI 整理 → 结构化入库 → 检索复用」清晰，三大模块与 Agent 中枢的联动关系明确，且给出了 Schema 与场景示例。**可以直接进入开发，但存在 1 个致命冲突和若干需要收敛的设计点**，处理如下。

## 二、关键问题与决策

### D1【致命冲突】技术栈：Python + Gradio/Streamlit × Flutter 二选一
原方案第四章写的是 Python + Gradio/Streamlit + Chroma，与已确认的「Flutter 原生应用（桌面 + 手机）」选型互斥：
- Gradio/Streamlit 是 Web UI，无法打包为 Android 应用；
- 「Flutter 前端 + Python 本地后端」的双栈方案在 Android 上无法随 APK 分发（需要打包 Python 运行时，不可行）；
- 方案中所有 Python 生态能力在 Dart/Flutter 中均有等价实现。

**决策：全 Flutter/Dart 单代码库，无独立后端。** 逐项替代：

| 原方案 | 替代方案 | 理由 |
|---|---|---|
| Gradio/Streamlit UI | Flutter Material 3 响应式 UI | 桌面 NavigationRail / 手机 NavigationBar 自适应 |
| Python requests/httpx | dio（SSE 流式解析） | OpenAI 兼容协议 + stream 均支持 |
| Chroma 向量库 | SQLite `embeddings` 表（BLOB 存向量）+ Dart 内存余弦相似度 | 个人知识库规模（<5 万条 × 1024 维）暴力扫描为毫秒级，无需独立向量库；且 Chroma 无 Android 支持 |
| SQLite（Python） | drift（Flutter 的 SQLite ORM） | 类型安全、支持 FTS5、桌面手机通用 |
| FastAPI 本地 HTTP API | **v1 砍掉，v2 仅 Windows 桌面版**（shelf 绑定 127.0.0.1） | 手机端无意义且不可行，见 D3 |

### D2【安全】API Key 存储
原方案「SQLite 加密存储、调用时解密」需要自研加密层（密钥又存哪里的问题）。
**决策：API Key 完全不进数据库**，使用 `flutter_secure_storage`（Windows 用凭据管理器、Android 用 Keystore），数据库中仅存 key 的引用名（如 `key_deepseek_main`）。更安全且少实现一套加密。

### D3【范围】v1 / v2 分层
原方案一次性交付面过大，单次工作流无法保证质量。**v1 只做核心闭环，进阶能力入 v2：**

v1（本次交付）：
- Agent 中枢：多厂商 Key 管理、`/models` 自动拉取、模型标签（启发式）、4 档思考强度、任务队列（异步 + 进度）、全链路 token 记账、单次/单日额度防护
- 模块1 灵感碎片：快捷录入、AI 优化（纠错/提炼/拆分/打标签）、双版本存储、转为提示词草稿/资料条目
- 模块2 提示词库：从碎片生成（3 风格版本）、定向优化（4 方向）、变量自动提取、版本历史与回滚
- 模块3 资料库：粘贴入库 + 单文件 TXT/MD 导入、五步入库向导（清洗→分类→Schema 映射→预览→入库）、内置 4 套 Schema（通用/官职/宝物/宗门）+ 用户可扩展、关联条目（双向链接）、FTS 关键词 + 语义混合检索
- 通用：设置页、用量统计页、GitHub 更新检查、数据导出/导入（Markdown + JSON 全量包）

v2（后续版本，本次不做但架构预留）：
- 批量资料治理（全库扫描/术语统一/补全建议）
- 自然语言知识问答（RAG 对话，多轮追问）
- 本地 HTTP API（仅 Windows）
- 语音输入、批量文件导入、AI 生成补全建议

### D4【诚实设计】模型能力标签
`/models` 接口不返回能力标签。**决策：规则引擎启发式标注**（模型名含 `reasoner|R1|thinking` → 深度推理型；含 `embed` → 嵌入向量型；上下文 ≥64k 标长上下文；其余通用对话型）+ 用户手动改。UI 上注明「自动标签为启发式」。

### D5【计费】费用估算
内置常见厂商价格常量表（token/百万），可自定义单价；查不到价格时只记 token 不估费。**不做精确对账，只做参考值。**

### D6【Schema 可扩展】
分类专属 Schema 不硬编码：以 JSON 文件形式放在应用数据目录 `schemas/` 下，应用首次启动写入 4 套内置 Schema，用户可自行编辑新增。Schema 结构见 `02-功能模块规格.md`。

### D7【检索降级】
语义检索依赖嵌入模型（DeepSeek 无 embedding 接口；通义/智谱有）。**决策：未配置嵌入模型时自动降级为 FTS5 关键词检索**，设置页引导配置。

### D8【GitHub 更新】
- 仓库含 `.github/workflows/ci.yml`（push 时 analyze + test）与 `release.yml`（打 tag `v*` 时构建 Windows 便携 zip + Android APK，发布到 GitHub Releases）
- 应用内更新检查：调 GitHub `releases/latest` API 比对 semver → 弹窗提示 → 桌面端打开 Release 页并引导替换；Android 端直接打开 APK 资产链接由系统下载安装。v1 不做静默热替换（Windows 静默更新需安装器框架，收益/复杂度比不划算）
- 仓库名在设置页可配置（owner/repo）

### D9【平台边界】
- 手机版 = Android（iOS 经 GitHub 分发不可行，不做）
- 桌面版 = Windows（macOS/Linux CI 可后续加）
- UI 全中文，代码标识符英文

## 三、v1 总体验收标准

1. `flutter analyze` 0 error；`flutter test` 全绿（见 `03-质量与发布.md`）
2. 冷启动即用：未配置任何 API Key 时，浏览/手动录入/检索均可用，AI 按钮置灰并引导跳转设置
3. 宽度 ≥900px 走侧边导航（NavigationRail），<700px 走底部导航（NavigationBar）
4. AI 任务全部经过队列与记账，额度超限自动拦截
5. 所有 AI 结构化输出经 Schema 校验，失败自动重试 ≤2 次后明确报错
