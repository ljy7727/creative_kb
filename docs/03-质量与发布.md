## 一、本地质量门禁（每个开发任务的完成条件）

环境：Flutter SDK 位于 `C:/Users/Admin/flutter`（Windows，Git Bash）。pub 镜像已通过用户环境变量 `PUB_HOSTED_URL=https://pub.flutter-io.cn`、`FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn` 配置；命令行调用时若变量未生效需显式内联：

```bash
cd /c/Users/Admin/.zcode/workspace/default/creative_kb
PUB_HOSTED_URL=https://pub.flutter-io.cn FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn \
  C:/Users/Admin/flutter/bin/flutter analyze   # 必须 0 error（warning 允许但尽量清）
PUB_HOSTED_URL=https://pub.flutter-io.cn FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn \
  C:/Users/Admin/flutter/bin/flutter test      # 必须全绿
```

drift 代码生成：改了 tables/daos 后必须 `dart run build_runner build --delete-conflicting-outputs` 再跑门禁。

## 二、测试策略（与实现同任务交付，不后补）

|---|---|---|
| core/llm | SSE 分帧解析、usage 提取/估算、类型化异常（401/429/5xx/网络断）、结构化输出：围栏剥离、Schema 校验、重试 ≤2 |dio 适配器 mock 假响应流 |

规模底线：每个 core 子模块 ≥6 个用例，features 每模块 ≥3 个关键路径用例。测试数据用规格文档中的「唐朝笏板」「青云宗」两个示例。

## 三、CI（.github/workflows/）

`ci.yml`：on push/PR → ubuntu-latest：checkout → subosito/flutter-action@v2 (stable, 中国镜像无需配置，GitHub 有网) → `flutter pub get` → `flutter analyze` → `flutter test`。

`release.yml`：on push tag `v*` → 两个 job：
- build-windows：windows-latest → `flutter build windows --release` → 压缩 `build/windows/x64/runner/Release/*` 为 `creative_kb-windows-amd64.zip`
- build-android：ubuntu-latest → `flutter build apk --release` → 产物 `app-release.apk` 改名 `creative_kb-android.apk`
- softprops/action-gh-action... 用 `softprops/action-gh-release@v1` 把两个附件 + 自动生成 notes 发到 Release

## 四、应用内更新（对应规格 A6）

见 `02-功能模块规格.md` A6。版本号唯一来源：`pubspec.yaml` 的 `version`（语义化 `major.minor.patch+build`）。发版流程：改 version → 打 tag → CI 出包 → 用户端检查更新提示。
